# 可移植性、隐私与恢复

可移植的 LitMan 文献库由 TOML 配置及其中指定的 SQLite 文件组成。这两个文件必须放在一起，`database` 应保持为旁边的普通文件名。PDF 目录相互独立，可以很大、位于移动介质，或由其他工具同步。普通操作可使用只读目录，但明确执行 PDF 替换时，选中文献的目录和文献库根目录必须可写。

数据库中的相对路径统一使用 `/`。打开时，LitMan 用当前 `library_root` 组合路径；只要文件位于根目录中，就不会把 Windows 盘符保存到单条记录。因此同一个已关闭的数据库可在 Windows、macOS、Ubuntu 和 CentOS 之间复制。复制后只更改根目录并扫描即可。

SQLite 使用 DELETE 日志、外键和繁忙超时。只有在全部 LitMan 进程关闭后才能安全地直接复制文件。运行时备份是安全的，因为它使用 SQLite 备份 API。请始终保存同一次备份操作产生的配置和数据库。

LitMan 没有遥测。PDF 元数据、备注、路径、分组和重要程度都留在本地。可选搜索/导入只会把配置的 bearer 令牌发送到 ADS API。明确执行 PDF 替换时会访问 SciXplorer 网关和解析到的出版商，但不会转发该令牌；登录后备流程会打开系统浏览器。浏览器还用于本地手册、PDF 及已存储的 SciXplorer 链接。

灾难恢复时应保存多个带日期的配置/数据库备份文件对，定期在另一台电脑验证，并为 PDF 目录制定独立备份策略。在线配置/数据库备份不包含 PDF 目录或替换目录 `LitMan-backups`。替换备份不受管理，必须手工恢复。恢复数据库无法重建丢失的 PDF；反过来，重新扫描 PDF 也无法重建丢失数据库中的手工备注和分组。
