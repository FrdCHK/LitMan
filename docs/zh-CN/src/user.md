# 用户手册

## 安装与卸载

Windows 用户运行 MSI，可选择是否把 `litman` 命令行程序加入 `PATH`。新版 MSI（包括同版本但源码已变化的重构建）会直接升级已安装版本，无需手工卸载。也可直接运行无需安装的便携版 EXE；当旁边没有手册目录时，其“手册”按钮会使用内置且可搜索的中英文用户手册。如果还需要 CLI 和完整的离线 mdBook 手册，请使用便携版 ZIP。从开始菜单启动已安装的 **LitMan**。可在“已安装的应用”中卸载；卸载程序不会删除文献库或 PDF。[Windows 10 的常规支持已于 2025 年 10 月结束](https://learn.microsoft.com/en-us/lifecycle/announcements/windows-10-22h2-end-of-support-update)，但 LitMan 仍将 Windows 10 22H2 作为首要测试目标。

点击工具栏中的“关于”可查看软件版本、作者 Jingdong Zhang 和 GNU GPLv3 许可证信息。

macOS 用户可打开 DMG 后把 LitMan 拖入“应用程序”，也可运行 PKG，同时安装应用和 `/usr/local/bin/litman`。Ubuntu 使用 `sudo apt install ./litman_版本_amd64.deb`。CentOS 7 使用 `sudo yum localinstall litman-版本.x86_64.rpm`。[CentOS 7 已于 2024 年 6 月停止维护](https://www.centos.org/centos-linux/)；LitMan 的兼容性不代表操作系统仍然安全。

## 新建和打开文献库

选择“新建文献库”，指定 `library.toml` 的保存位置，再选择包含 PDF 的目录。配置和数据库存放在一起：

```toml
schema_version = 1
database = "literature.sqlite3"
library_root = "../pdfs"
language = "system"
# 可选；个人令牌可在 ADS 用户设置页面中获取。
scixplorer_api_token = "你的个人令牌"
```

`scixplorer_api_token` 行是可选的，新建配置默认不包含该项。数据库名必须解析为配置文件旁的文件。相对根目录从配置文件目录开始解析，也可使用绝对目录。扫描会包含所有子目录。

## 扫描

打开文献库后会自动进行增量扫描。“扫描”可再次执行；“刷新元数据”还会重新读取未改变文件的内嵌元数据。扫描具有以下规则：

- 不跟随目录符号链接，并拒绝规范路径位于根目录之外的文件；
- 根据文件大小和修改时间跳过未改变文件；
- 对新增或改变的文件计算 BLAKE3 哈希，并识别唯一明确的移动；
- 缺失文件的记录和元数据仍然保留；
- 相同内容的多个副本会被标记，但不会自动合并；
- 损坏或加密文件的错误只记录到该文件，不会中断整个扫描。

扫描期间界面仍可使用，并可点击“取消”。取消后已经完成的记录会保留，可以随时继续扫描。

## 元数据与手工修订

选择论文后，可编辑标题、按顺序排列的作者、摘要、出版日期、期刊或会议、卷、期、页码、DOI、URL、语言、按顺序排列的关键词以及备注。界面中的作者和关键词使用分号分隔，然后点击“保存”。

LitMan 会读取 PDF Info 和常见 XMP、Dublin Core、PRISM 字段。最终显示值的优先级如下：

1. 用户手工值；
2. ADS/SciXplorer BibTeX 或 arXiv Atom 值；
3. XMP 值；
4. PDF Info 值；
5. 空值。

重新扫描绝不会覆盖手工值或外部导入值。“恢复 PDF 内嵌元数据”会删除指定字段的手工值及外部来源，让当前内嵌值重新显示。没有元数据时，文件名仅作为界面占位文字；除非用户输入，否则不会保存成题名。

## 从 ADS/SciXplorer 或 arXiv 导入文献

点击“导入文献”，输入一个标识符或链接。LitMan 会自动识别 ADS bibcode（如 `2003ApJ...587..208R`）、现代或旧式 arXiv ID（如 `0908.3637`、`astro-ph/9901234v2`）、ADS 摘要链接以及 arXiv `/abs/` 或 `/pdf/` 链接。arXiv 导入无需凭据；只有在“SciXplorer 设置”中配置个人 ADS 令牌后，ADS 导入才可用。

ADS 导入会获取精确记录的 BibTeX 和 `esources`，优先使用 `PUB_PDF`；仅当正式版来源明确不可用时才改用 `EPRINT_PDF`。若出版商返回登录页或 HTML，使用浏览器后备流程：下载出版商 PDF 后点击“选择已下载的 PDF”，所选源文件不会改变。arXiv 导入会同时取得 Atom 记录和 PDF，包括有序作者、摘要、日期、DOI、期刊引用、分类、规范链接及原始 Atom 响应。

成功后，文件在文献库根目录固定命名为 `BIBCODE.pdf` 或 `arXiv-ID.pdf`（旧式 ID 的 `/` 替换为 `_`）。LitMan 不覆盖文件，也不会自动添加编号；若规范化提供方 ID、目标路径或内容哈希已存在，将拒绝整个导入。元数据与 PDF 一起提交，取消或失败后不会留下记录或目标文件。下载仅允许 HTTPS，最大 256 MiB，并在安装前检查 `%PDF-`、解析 PDF 和计算哈希。ADS 令牌只发送给 ADS API，绝不会发送给出版商网关、arXiv 或重定向目标。

## 可选的 SciXplorer 元数据与 BibTeX

LitMan 可使用为 SciXplorer 提供数据的 [ADS Developer API](https://github.com/adsabs/adsabs-dev-api)。此功能完全可选。未配置令牌时，LitMan 不会向 SciXplorer/ADS 发送请求，元数据侧栏中的 **SciXplorer** 按钮也不可用。

先在 [ADS 令牌设置](https://ui.adsabs.harvard.edu/#user/settings/token)中生成个人 API 令牌。在 GUI 中点击“SciXplorer 设置”，输入令牌后点击“保存令牌”。令牌以明文写入该文献库的 `library.toml`，备份或复制配置时也会被包含。请像保护密码一样保护此文件，切勿提交或分享。“删除令牌”会禁止新的搜索和导入，但不会删除数据库内已经保存的 BibTeX。

选择一篇文献，在元数据侧栏点击 **SciXplorer**，可按标题、DOI 或 ADS/SciXplorer bibcode 搜索。LitMan 最多显示 20 条匹配记录。点击“使用”后，会下载并原样保存该记录的 BibTeX 到 SQLite，同时把其中可用的标题、有序作者、摘要、出版日期、期刊或会议、卷、期、页码、DOI、URL、语言和关键词写入元数据。导入值会替换对应的当前值；如果新 BibTeX 缺少上一次 BibTeX 曾提供的字段，该字段会恢复为 PDF 内嵌值。之后的手工修改优先，并标记为手工来源。

保存 BibTeX 后，点击 **BibTeX** 会复制到系统剪贴板并显示确认消息。“打开 SciXplorer”会用默认浏览器打开 `https://scixplorer.org/abs/BIBCODE/abstract`。这两个按钮使用数据库中已经保存的数据，因此即使删除 API 令牌后仍然可用。

### 用正式发表版替换预印本

对于一篇存在且已保存 bibcode 的文献，即使删除 API 令牌，“更新 PDF”仍然可用。它访问 `https://scixplorer.org/link_gateway/BIBCODE/PUB_PDF`；ADS bearer 令牌绝不会附加到该请求或出版商重定向。居中的警告窗口会列出当前 PDF 及其备份、单独存在的未跟踪 `BIBCODE.pdf` 及其额外备份，以及最终的 `BIBCODE.pdf`。请先关闭 PDF 阅读器，阅读警告并勾选确认框，再点击红色“替换 PDF”。取消不会开始下载，也不会改变文件系统或数据库。

LitMan 先把内容下载到同一文件系统中的临时文件，限制为 HTTPS、有限重定向和超时、最大 256 MiB，并检查 `%PDF-` 文件头、解析 PDF、计算哈希；全部通过后才移动文件。当前文件始终准确命名为 `BIBCODE.pdf`，绝不会使用带编号的当前文件名。若该名称是未跟踪文件，它也会被保留；若属于另一条 LitMan 记录，则在不做任何更改的情况下拒绝替换。若出版商返回登录/HTML 页面，窗口会保留并提供“打开出版商链接”“选择已下载的 PDF”和“取消”。选择外部下载文件时会复制并验证，原下载文件不受影响。

被替换文件放在文献库根目录的 `LitMan-backups` 中，依次命名为 `BIBCODE_bk.pdf`、`BIBCODE_bk_2.pdf` 等。LitMan 会标记自己创建或在空目录时接管的目录，扫描仅排除带标记的备份目录。若同名目录非空且没有标记，替换会被拒绝，该目录仍会被扫描。备份不受 LitMan 管理，必须手工恢复。待处理清单使启动、扫描和后续替换能够回滚提交前中断，或在数据库已经提交后完成清理；如果哈希不符合清单，程序会保留全部文件并报告错误，而不会猜测。

## 查找和整理文献

搜索会在元数据、作者、关键词、备注、文件名/路径和分组名中进行字面匹配。文本先进行 Unicode NFKC 规范化并转换为小写。中文使用子串搜索，不依赖中文分词。

可创建类似 `课题/方法` 的嵌套分组。重复路径会被拒绝并显示警告，创建成功后也会在通知区域显示消息。一篇论文可以属于多个分组。在中间列表中单击一行以选择文献，或按住 Ctrl/Command 单击以多选。然后在左侧始终可见的“将所选文献加入分组”区域选择目标分组，并点击“加入分组”或“从分组移除”。单击分组树中的分组只会筛选列表，不会把文献加入分组。选择分组并点击“重命名分组”后，可在小窗口中输入新名称；同一父分组下的名称不能重复。重命名会保留嵌套分组及其分组关系。要删除所选分组及其所有嵌套分组，请点击“删除分组”并确认。分组关系会被移除，但不会删除文献记录或 PDF。

拖动各列表头之间的分隔线可调整文献列表列宽。调整后的列宽在当前 LitMan 运行期间保持有效。

重要程度可以为空，也可以选择一至五星，五星表示最重要；`×` 用于清除。多选后可批量修改。英文显示 **Importance**，简体中文显示 **重要程度**。

状态筛选可显示存在、缺失或出错的记录。重要程度、分组和搜索条件可以组合使用。

“本次新增”（**Newly added**）是独立的 GUI 筛选项，可与搜索、分组、重要程度及状态一起使用。它包含本次 LitMan 进程启动后由扫描或成功在线导入首次建立的记录；已有记录、识别出的移动、仅更新 SciXplorer 元数据和 PDF 更新都不计入。运行期间每个文献库各自保留集合，LitMan 退出后即丢弃。

## 打开与移除

“打开”会调用操作系统的默认 PDF 阅读器。“移除数据库记录”经确认后仅删除 LitMan 中的记录。所有普通操作都保持 PDF 只读；只有上文所述、明确确认的“更新 PDF”流程会移动和替换 PDF。

## 备份、复制与恢复

程序运行时使用“备份”或 `litman backup 目标目录`。该操作通过 SQLite 在线备份 API 创建一致的配置/数据库文件对，但不包含 PDF 目录或 `LitMan-backups`；请为二者制定独立的文件备份策略。如果直接复制文件，必须先关闭所有 LitMan 进程，再同时复制 TOML 和 SQLite 文件。

换电脑时，复制或挂载 PDF 目录，打开复制后的 TOML，然后选择“更改根目录”或执行 `litman root set 目录`。数据库内的相对 PDF 路径统一使用 `/`，因此只需更改根目录。不要把不同备份中的配置和数据库拼在一起。

恢复时关闭 LitMan，用同一次备份中的两个文件替换现有文件。在恢复库成功打开并扫描之前，请保留额外副本。

## 升级与错误处理

旧版程序可能拒绝打开新版数据库。升级前请先备份。数据库迁移在事务中完成，不会改变 PDF。

文件显示缺失时，请检查根目录后重新扫描。解析错误会保留诊断信息，必要时仍可手工输入元数据。数据库繁忙时，请关闭其他 LitMan 进程再重试。如果 Windows 上 GPU 渲染器初始化失败，LitMan 会自动改用 OpenGL 重试。

LitMan 没有遥测。普通的文献库、PDF、搜索、整理和备份操作全部在本地完成。SciXplorer 搜索或导入会把配置的令牌及查询/bibcode 发送到 ADS API。arXiv 导入会把所需 ID 发给 `export.arxiv.org`，并从 `arxiv.org` 下载 PDF。在线导入和正式版替换会访问所选远程来源，但不会转发 ADS 令牌；浏览器后备流程也会由系统浏览器访问相关网站。
